## 结论

跑完的年份（2018、2019、2021、2022、2023、2024，以及补完后的 2020）“有 LST 无 LSCT2”的比例稳定在 **8~10%**，那是极夜/云掩膜全灭导致的正常空结果。以此为基线，真正的缺口是：

| 缺口 | 规模 | 能否直接补 |
|---|---|---|
| 2017 年缺 LSCT2（约 5602 景） | 有 LST 输入 11690 景，出成果 5001 景 | 可以，直接跑 `slstr_lsct2_parallel.py` |
| 2025 年缺 LSCT2（约 2056 景） | 有 LST 输入 11150 景，出成果 8007 景 | 可以，直接跑 `slstr_lsct2_parallel.py` |
| 2020 年 11—12 月提取缺口（1650 景） | 其中 2020-11 617 景、2020-12 822 景没有 tif 输入 | 不行，要先拿回原始 .SEN3 |
| 2020 以外各年的零星提取缺口（1312 景无 tif、679 景不全，其中 662 景只缺 cloud_obliq.tif） | 约 2% 量级，分散在各月 | 不行，同样要补原始产品 |

另外 2017 年还有 **1415 景缺 LST 成果**（2017-02 最集中，855 景），需要先补 LST 才能谈 LSCT2。

## 处理建议

1. 可直接补跑 LSCT2（有 LST 输入、只是没算）：

```bash
cd /home/hero/work/ls4t
PYTHONPATH=. python cases/slstr/implementation/one_by_one/slstr_lsct2_parallel.py \
    --year 2017 --workers 48 --report cases/slstr/regions/lsct2_2017_completion.json
PYTHONPATH=. python cases/slstr/implementation/one_by_one/slstr_lsct2_parallel.py \
    --year 2025 --workers 48 --report cases/slstr/regions/lsct2_2025_completion.json
```

2. 缺 LST 的景（2017 年 1415 景）重跑 `cases/slstr/implementation/one_by_one/slstr_lst.py`；
3. 提取缺口（2020-11/12 为主，含各年零星缺 cloud_obliq 的景）需要原始 .SEN3，目前挂载的盘上没有 raw 数据，要先重新下载再解压、提取、LST、LSCT2 依序重跑；
4. 无有效像元的景（极夜、云掩膜全灭）不用处理。
